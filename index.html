Case Study 01

OpsFlow AI

SaaS Concept
Role: Product Designer Duration: 4 weeks Tools: Figma · Lovable · Notion

Problem

Remote teams juggling Slack, Notion, and Jira lose context switching between them. No single surface combines task management with AI-generated status insights and visual workflow automation — leaving PMs and ops leads manually stitching information together.

Process

Discovery

Mapped pain points of 5 remote team personas (PM, Dev, Designer, Ops Lead, Founder); identified top 3 context-switching triggers

Define

Narrowed to 3 core jobs-to-be-done: track work, understand status, automate repetition

Design

Built full IA, component library, and 12-screen high-fidelity Figma prototype; designed AI summary card system

Prototype

Built interactive workflow builder in Lovable; ran 3 peer usability sessions and iterated on node editor layout

Key Screens

Outcomes

  • Task status lookup reduced from 4 clicks to 1 via persistent AI summary card
  • Workflow builder “create a trigger” task completed at 100% by 3 peer testers with no guidance
  • Dashboard layout scored 4.6/5 on perceived clarity (informal 5-person usability session)

What I'd Do Next

Real Supabase backend for live task sync · Multi-workspace support · AI prompt customisation per team

Case Study 02

Campus Commerce System

Marketplace Concept
Role: Product Designer Duration: 3 weeks Tools: Figma · Paper · Notion

Problem

Students at large Nigerian universities rely on informal WhatsApp groups and verbal communication to order food and goods from campus vendors. There is no structured ordering, inventory tracking, or vendor management layer — creating friction for students and lost revenue for vendors.

Process

Discovery

Observed campus vendor-student transactions at LASU; documented 4 core friction points in the order-to-delivery flow

Define

Scoped MVP to 3 actor types: Student, Vendor, Admin; mapped each actor's primary jobs-to-be-done

Design

Designed student ordering flow (browse → cart → confirm → track), vendor dashboard (orders + inventory), and admin panel (vendor approval + analytics)

Prototype

Paper-to-Figma flow; tested ordering flow with 4 LASU students; iterated on cart confirmation step

Key Screens

Outcomes

  • Full student order flow condensed to 3 steps from product discovery to confirmation
  • Vendor onboarding form completed in under 4 minutes by all test participants
  • Admin permission hierarchy validated as clear and unambiguous in peer design review

What I'd Do Next

Campus GPS delivery zone logic · Lightweight PWA shell · Vendor notification system

Case Study 03

AI Workflow Builder

Automation UX Prototype
Role: Product Designer Duration: 3 weeks Tools: Figma · Lovable

Problem

Non-technical operators want to automate repetitive tasks (e.g. “when a form is submitted, summarise with AI and notify the team”) but tools like Zapier overwhelm them with complexity and don't natively support AI-step logic. The cognitive load of learning trigger/action/filter paradigms creates drop-off before the first automation is built.

Process

Discovery

Audited UX patterns in Zapier, Make, and n8n; identified 3 primary cognitive load bottlenecks for non-technical users

Define

Simplified automation model to 3 node types only: Trigger, Action, AI Step — progressive disclosure hides advanced config

Design

Visual canvas with drag-and-connect node editor; designed AI Step config panel (input → prompt template → output mapping)

Prototype

Built 2 sample automation flows as interactive prototype; tested with 2 non-technical participants

Key Screens

Outcomes

  • 3-node model reduced conceptual complexity vs. 7+ node types in comparable tools
  • “Build your first automation” onboarding flow completed at 100% by both non-technical test participants with no prompting
  • AI step configuration pattern (input → prompt → output) rated as intuitive by all testers

What I'd Do Next

LLM prompt templates per industry use-case · JSON export for developer handoff · Conditional branching (if/else) node type
